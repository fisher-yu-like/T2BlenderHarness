# T2Blendercodeharness 五轮小批量训练日志

创建日期：2026-08-25  
目标：固定 10 个 train + 10 个 dev case，连续运行五轮 Harness 训练，逐 case 记录分数、proxy job/视频地址、错误、修复和前后变化。

## 1. 实验约定

### 1.1 固定样本

每轮使用完全相同的 20 个 case：

| Split | Case IDs | 选择理由 |
|---|---|---|
| train | `hard-01-01` 至 `hard-01-10` | supported baseline family，作为可学习的训练压力样本 |
| dev | `hard-07-01` 至 `hard-07-10` | novel spatial transfer family，测试未见组合泛化 |

不使用 test case 选择 patch、调整规则或决定 owner。test 保持冻结，五轮结束后再单独报告。

### 1.2 每轮流程

```text
固定 10 train + 10 dev
  → current Harness 生成 contract/trajectory/camera/proxy job
  → deterministic + independent-oracle score
  → 只使用 train failure 聚合问题
  → 选择一个 owner
  → 修改一个 Harness 组件
  → 重新跑同一批 10 train + 10 dev
  → 记录提升/下降和自然语言处理结论
```

### 1.3 “同一批”定义

固定的是 prompt、proxy scene、case IDs、split、evaluator、backend 和 seed。候选 Harness 必须重新生成自己的 plan/job/video，不能把上一轮的视频直接作为本轮结果。

当前环境没有 Blender executable/MCP 执行结果，所以 proxy video 字段会记录预期 `proxy.mp4` 地址，并标注 `NOT_RENDERED`；job 地址必须是真实生成并编译过的 immutable `blender_job.py`。

### 1.4 评分

当前采用 `deterministic-v2-independent-oracle`：

```text
deterministic_score = max(0, 100 - 25 × deterministic_findings)
final_score = deterministic_score - 15 × independent_oracle_findings
```

这里的分数不是 VLM 视频质量分数。真实视频必须通过 artifact gate 后才能进入 VLM。

### 1.5 接受标准

每轮 patch 只有满足以下条件才接受：

```text
train_after > train_before
dev_after >= dev_before
hard_dev_regression == false
```

如果下降：保留失败记录，执行 rollback 或停止该 owner，不把下降结果覆盖掉。

## 2. 五轮预定修复策略

这是执行顺序，不代表预先假设每个 patch 一定成功；每轮必须以 train failure evidence 决定最终 owner。

| 轮次 | 首选观察方向 | 允许的主要 owner |
|---:|---|---|
| 1 | parser 对支持语义、目标实体和动作顺序的表达 | `scene_parser` |
| 2 | novel spatial transfer 的轨迹 primitive、path shape、attachment | `trajectory_planner` |
| 3 | follow/orbit/dolly/hold/reveal 的镜头覆盖和意图 | `camera_planner` |
| 4 | proxy scene entity、support/occluder/assistant 的执行绑定 | `blender_executor` 或 `proxy_renderer` |
| 5 | 综合回归和 remaining repeated failure；只允许一个 owner | 由 train evidence 决定 |

如果实际 train failure 与首选方向不一致，以实际 failure owner 为准。

## 3. Memory 规则

每轮单独拥有 Memory event chain：

```text
proposal
patch_applied
train_evaluated
dev_evaluated
accepted / rejected / rollback / no_patch
```

每条记录必须保存 parent/candidate Harness version、owner、dataset/evaluator fingerprint、affected case IDs、score before/after、evidence 和自然语言 reason。
